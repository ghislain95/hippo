# Design

## Context

See proposal.md (Why, What Changes, « After the adversarial pass ») and mockups.md (screens 1 to 12). State on 2026-11-13:

- `app/` is the walking skeleton: Expo SDK 58, React Native 0.88.1, `expo-router` with a `Stack`, the generated `openapi-fetch` client, `src/config.ts` reading `extra.apiUrl` and `extra.apiToken` from `app.config.ts`, which falls back silently to `http://127.0.0.1:8080` and an empty token. `ServerStatus` calls `GET /healthz`. No theme, no native target, `ios/` git-ignored.
- The E1 prototype (commit 372efc3, removed by 672cc3e) proved the chain: Swift extension generated by `@bacons/apple-targets` 5.0.0, no App Group, JSON and multipart requests, 26 to 29 MB of memory, 0.7 s to send a large photo in 5G. Its code is a reference, not a base: it decoded the whole image, built the multipart body in memory, took the first image type offered (always JPEG on the iPhone) and showed measures.
- `api/openapi.yaml` (`createItem`) is unchanged: JSON body 1 MiB at most, strict members; multipart body 21 MiB, `image` 20 × 1 048 576 bytes, text parts 1 MiB; upload allowed 5 minutes; `200` for a duplicate link or a replayed `client_id`; `Problem.detail` is optional.
- `@bacons/apple-targets` 5.0.0 (read from its npm tarball, the version the change pins; it is not installed yet):
  - each `targets/<name>/` holding an `expo-target.config.js` becomes a target (`build/config-plugin.js:28`, glob `targets/*/expo-target.config.@(json|js)`);
  - the whole folder is a `PBXFileSystemSynchronizedRootGroup`: every file in it, recursively, belongs to the target, except `Info.plist` and the config file (`build/with-xcode-changes.js:342-369`);
  - a missing `Info.plist` is written at `prebuild` with `NSExtensionActivationRule: TRUEPREDICATE` for a share target (`build/target.js:445-453`), and never rewritten once present (`build/with-widget.js:204-208`);
  - share targets default to App Groups, but the default and its warning only apply when the target config defines `entitlements` (`build/with-widget.js:105-130`, inside `if (entitlementsJson)`): without any, nothing is printed (verified in task 1.2, As built);
  - `colors: { name: { light, dark } }` in the target config generates colour sets (`build/config.d.ts` `DynamicColor`, `withConfigColors`; the README's `color`/`darkColor` is out of date, As built); the config may be a function of the Expo config, CommonJS only (README, « ESM and TypeScript are not supported in the target config »);
  - `ios.appleTeamId` is read from the Expo config, with a warning when missing (`build/config-plugin.js:16-26`);
  - the package autolinks an Expo module, `ExtensionStorage` (`expo-module.config.json`, `ios/ExtensionStorage.podspec`), unused here;
  - it needs CocoaPods 1.16.2 or later and Xcode 16 or later (README « How to use »).
- SwiftPM 6.4 (Xcode on the Mac) refuses a target path outside the package root: `error: target 'Core' in package 'pkg' is outside the package root` (tried on 2026-11-13 in a scratch package).
- `expo-router` 58 re-exports `ThemeProvider`, `DarkTheme` and `DefaultTheme`, and the type `Theme` (`app/node_modules/expo-router/build/exports.d.ts:24-29`, checked on the installed 58.0.31 in task 5.1). `expo/tsconfig.base` (SDK 58) sets `resolveJsonModule: true`, so the app imports `tokens.json` without any change to `tsconfig.json` (checked in task 5.1).
- `expo/config-plugins` (`@expo/config-plugins` 58.0.12) exports `withDangerousMod` and `withInfoPlist` (`app/node_modules/@expo/config-plugins/build/index.d.ts:22,25`, same checkout).

## Goals / Non-Goals

**Goals:**

- A share extension whose every decision (form, body, size, id, screen) is pure logic tested by `swift test`, and whose UIKit and SwiftUI layer only loads, displays and sends.
- One build-time configuration for the app and the extension, that fails loudly instead of building an app that cannot talk to its server.
- Stay within the extension's memory with a 20 MB original image.

**Non-Goals:**

- Building the extension target in CI (too slow for the gain; replaced by a local build in the definition of done, D13).
- A generated Swift client: the extension hand-writes two request shapes, pinned by tests against the contract's members (ADR-0036).
- Any network call from the extension other than `POST /api/items` (no page title fetch, no `/healthz`).

## Decisions

### D1 — Build-time configuration: one check, one generation step

- Variables: `HIPPO_API_URL` (default `http://127.0.0.1:8080`), `HIPPO_API_TOKEN` (required), `HIPPO_APPLE_TEAM_ID` (optional, mapped to `ios.appleTeamId` for a signed device build; never committed, as the runbook already says).
- A local config plugin, `app/plugins/with-share-config.js` (CommonJS, `expo/config-plugins`, no new package), added to `plugins` in `app.config.ts` after `@bacons/apple-targets`:
  - its pure part, `checkBuildConfig(env)`, returns `{ url, token }` or throws; jest tests it (spec app-shell, « The build refuses… »);
  - rules: token of 32 characters or more, only `A-Z a-z 0-9 - . _ ~ + / =` (so it is a safe string literal in Swift and JS); URL parsed by `new URL`, `https`, or `http` on `127.0.0.1` or `localhost` only (the simulator; on a device that address is the phone itself); trailing slashes removed;
  - error messages name the variable and the rule, never the value;
  - its `ios` dangerous mod runs only at `prebuild` (never at `expo config`, `expo-doctor` or jest, which have no variables in CI): it checks, then writes `app/targets/share/BuildConfig.generated.swift` (`enum BuildConfig { static let serverURL: URL; static let apiToken: String }`, header « generated by app/plugins/with-share-config.js, never edit, never commit »). The synchronized group makes it part of the target without any Xcode change.
- `app.config.ts` keeps reading the same variables into `extra` for the app. The app's `Info.plist` gets `NSAllowsLocalNetworking` only when the URL is `http` (prototype pattern), through `ios.infoPlist`.
- `.gitignore`: `app/targets/share/*.generated.swift`. gitleaks runs at pre-commit and in CI as a second net.
- Changing the URL or the token means `npx expo prebuild --clean` then a build: the two scripts of D13 always run both in one command, with the same environment, so the app and the extension never diverge. Building from the Xcode GUI is not supported (its build phases do not see the shell's variables; the app would embed an empty token).
- The token stays readable in the built app and extension, as in the JS bundle: accepted (ADR-0016, ADR-0027).

Alternatives: build settings or `INFOPLIST_KEY_*` (apple-targets exposes no build setting; a dictionary key cannot go through `INFOPLIST_KEY_*`); a script run by hand before `prebuild` (the prototype's; forgotten once, the build uses a stale token); failing in `app.config.ts` (would break `expo-doctor` and jest in CI).

### D2 — Versioned `Info.plist` and activation rules

`app/targets/share/Info.plist` is committed and static:

- `NSExtensionActivationRule` dictionary: `NSExtensionActivationSupportsWebURLWithMaxCount` 1, `NSExtensionActivationSupportsText` true, `NSExtensionActivationSupportsImageWithMaxCount` 1; no file, attachment or movie key;
- `NSExtensionPointIdentifier` `com.apple.share-services`, `NSExtensionPrincipalClass` `$(PRODUCT_MODULE_NAME).ShareViewController`;
- `NSAppTransportSecurity` with `NSAllowsLocalNetworking` true only, for the simulator against `http://127.0.0.1:8080`. A device build cannot use it: D1 refuses any `http` URL that is not loopback. Its exact scope on iOS 27 is unverified; the device build's `https` URL needs no exception (ADR-0015, E1-03).
- `expo-target.config.js`: `type: 'share'`, `name: 'HippoShare'`, `displayName: 'Hippo'`, `bundleIdentifier: '.share'`, `deploymentTarget: '18.0'` (prototype), `colors` from D10, no `entitlements` (so no App Group, ADR-0013, ADR-0014). Without `entitlements`, the prebuild prints no App Group warning (As built); an App Group is never added (runbook).

A `swift test` reads this file and checks the keys (spec share-extension, « The extension is offered… »).

Alternative: the plugin's default `TRUEPREDICATE` (offers the extension for files and several photos, against the decision of 2026-11-13).

### D3 — Swift layout: one package at `app/targets/`, compiled twice

```
app/targets/
├── Package.swift               swift-tools-version 6.0; platforms iOS 18, macOS 14
├── .swift-format               versioned rules (D12)
├── share/                      the extension target (apple-targets)
│   ├── expo-target.config.js, Info.plist, BuildConfig.generated.swift (ignored)
│   ├── ShareViewController.swift, ShareView.swift, ShareModel.swift,
│   │   AttachmentLoader.swift, CaptureSender.swift        UIKit, SwiftUI, NSItemProvider, URLSession
│   └── Core/                   pure logic: Foundation, UniformTypeIdentifiers, ImageIO only
└── ShareCoreTests/             swift test (Swift Testing), no expo-target.config: ignored by apple-targets
```

- `Package.swift` declares the library `ShareCore` at `path: "share/Core"` and the test target `ShareCoreTests` at `path: "ShareCoreTests"`. SwiftPM needs the sources under the package root (verified, see Context); apple-targets compiles everything under `share/`, so `Core/` is also part of the extension's own module: the extension never writes `import ShareCore`, the tests write `@testable import ShareCore`.
- No `Package.swift`, test or `XCTest`/`Testing` import may live under `share/`: it would be compiled into the extension.
- `.gitignore`: `app/targets/.build/`, `app/targets/.swiftpm/`.
- Verified first, in task 1.2, by `prebuild --clean` and a simulator build: the target compiles `Core/`, ignores `Package.swift` and `ShareCoreTests/`. If not, the fallback is the `exceptions` of the synchronized group, set by our config plugin (unverified).
- **Result of task 1.2 (2026-11-13, Xcode 27.1, Swift 6.4, iOS 27.1 simulator SDK, `@bacons/apple-targets` 5.0.0): the layout holds, no fallback.** `swift test` passed (Swift Testing); `npx expo prebuild --clean -p ios` then `xcodebuild` Debug for `generic/platform=iOS Simulator`, unsigned, succeeded. The generated project has one `PBXFileSystemSynchronizedRootGroup` with `path = share` under the `expo:targets` group (`path = ../targets`), its exceptions being `Info.plist` and `expo-target.config.js` only; the build log compiles exactly `share/ShareViewController.swift` and `share/Core/Probe.swift` into `HippoShare`, never `Package.swift` nor `ShareCoreTests/`. The SHA-1 of `share/Info.plist` is unchanged by the prebuild, and the built `HippoShare.appex/Info.plist` holds its activation rule and `NSAllowsLocalNetworking`. No App Group output at all (see As built). `make doctor-app` stays green with the plugin.

Alternatives: a package outside `targets/` pointing into `share/` (refused by SwiftPM); a local package dependency of the target (apple-targets has no option for it, the Xcode project is regenerated); copying the sources (drift).

### D4 — Reading the share, then choosing the form

The UIKit layer (`AttachmentLoader`) turns the `NSExtensionItem` attachments into a `SharedContent`, without loading any image bytes:

- every `public.url` value (as `URL`), every `public.plain-text` value (as `String`), and, for each provider conforming to `public.image`, its registered type identifiers and the provider itself;
- the attributed title of the first item, if any, for the link preview (no network).

`Core` decides (`CaptureChoice`, spec share-extension):

1. the first URL with scheme `http` or `https` (any case), else the first text that, trimmed, parses as an `http` or `https` URL with a host and holds no whitespace → link;
2. else the first image provider whose type can be loaded (D5) → image;
3. else the first text not blank after trimming → note;
4. else nothing-to-save.

For a link or an image, the accompanying text comes from the texts not used as the URL: in each, every occurrence of the captured URL's exact string is removed, then it is trimmed; the first one left non-empty prefills the capture note (none: the note starts empty). A note has no capture note field (RG-07).

The order follows Ghislain's decision of 2026-11-13; its French wording for RG-01 is below (Decisions to confirm).

### D5 — Image: closed list, file on disk, ImageIO

- Type: the first of `UTType.heic`, `.png`, `.webP`, `.jpeg` that the provider registers, by conformance, in this order. None of them → the first registered type conforming to `public.image` is loaded and converted to JPEG (ImageIO, `CGImageDestination`, quality 0.9, orientation kept as a property). An image that ImageIO cannot read → nothing-to-save.
- Loading: `loadFileRepresentation(for:)`; inside its completion handler the file is copied to the extension's temporary directory as `<capture id>.<ext>` (the given URL is only valid there). The bytes are never held in memory.
- Size: file size from the file system, after any conversion; over 20 971 520 bytes → too-large at once, the form is never shown. `Core.SizeText` formats bytes / 1 048 576, one decimal rounded up, French comma: `20,1 Mo`.
- Thumbnail: `CGImageSourceCreateThumbnailAtIndex` from the file URL, `kCGImageSourceThumbnailMaxPixelSize` 600, `kCGImageSourceCreateThumbnailWithTransform` true, `kCGImageSourceCreateThumbnailFromImageAlways` true. The image is never decoded at full size for the preview. Apple documents this as decoding a reduced image; its peak memory on a 48 Mpx HEIC or a large PNG is unverified until the QA (Risks).
- Caption: `Image · <HEIC|PNG|WebP|JPEG> · <size>` (screen 4).
- Temporary files (image, multipart body) are removed when the sheet closes; iOS purges the directory anyway.

### D6 — Requests

- `POST <serverURL>/api/items`, headers `Authorization: Bearer <token>`, `Accept: application/json`, `Content-Type` per body. `URLSessionConfiguration.ephemeral` (no cookie, no cache: the extension stores nothing, ADR-0014).
- Link or note: JSON built by `Core.CaptureBody` with `JSONEncoder`, members in the contract's snake_case only: `url` or `note`, `user_note` when not blank, `is_private` always, `client_id`, `source: "share"`. Values trimmed (RG-09). Body over 1 048 576 bytes → too-long, not sent.
- Image: `Core.MultipartWriter` streams to a temporary file: boundary `hippo-<capture id>`, part `image` (`filename="capture.<ext>"`, `Content-Type` of the picked type), then `user_note` when not blank (over 1 048 576 bytes → too-long), `is_private` `true`/`false`, `client_id`, `source` `share`; the image is copied in 1 MiB chunks. Sent with `URLSession.upload(for:fromFile:)`.
- Capture id: `Core.Ulid`, 48-bit Unix time in milliseconds then 80 random bits from `SystemRandomNumberGenerator`, Crockford base 32, 26 characters (ADR-0035). Drawn once when the sheet opens. No library.
- « Réessayer » resends the same `URLRequest` and the same body (same `Data` or same file): same bytes, same capture id (RG-08). The form is frozen from the first tap on Enregistrer.

### D7 — Time limits

- `timeoutIntervalForRequest` 10 s: the longest wait without any byte, which includes resolving the name and opening the connection. A NAS that does not answer behind an active Tailscale is told unreachable within about 10 s; Tailscale off fails at once (the `.ts.net` name does not resolve).
- `timeoutIntervalForResource` 30 s for JSON, 330 s for an image (the server allows 5 minutes, plus margin), so a 20 MB image on a slow mobile network keeps the time it needs as long as bytes flow.
- `waitsForConnectivity` false.
- Source: Apple's `URLSessionConfiguration` documentation (the request timer is reset whenever new data arrives); its behaviour on the upload side is unverified, measured in the QA.

### D8 — Answers to screens

`Core.Outcome.classify(answer, form, attempt, sentNote)`, spec share-extension:

| Answer | Screen |
| --- | --- |
| no answer (`URLError` other than cancelled), any `5xx` | 7 unreachable, « Réessayer », copy action (link, text; none for an image) |
| `401` | 11 token refused |
| `413` with type `urn:hippo:problem:image-too-large` | 8 too large |
| any other `4xx`, other `413` included | 10 refused, `detail` as is, else the fallback text |
| `201` | 5 saved, or 12 saved-private when the answered item's `is_private` is true |
| `200`, link, attempt 1 | 6 duplicate, with or without a note |
| `200`, otherwise | 5 or 12, as `201` |
| `1xx`, `3xx`, other `2xx` | 10 refused, fallback text |
| no answer to classify: the request body cannot be written on the phone (multipart file), before any send | 13 preparation failure, « Fermer », nothing sent (validated by Ghislain on 2026-11-13) |

The answered item is decoded for `is_private` only; an undecodable `2xx` body falls back to the switch's value. A duplicate made private by the capture (RG-15) still shows screen 6.

### D9 — States of the sheet

`loading` → `form` | `tooLarge` | `nothingToSave`; `form` → `sending` (Enregistrer; form frozen, progress on the button) | `tooLong` | `preparationFailed` (the body cannot be written on the phone, screen 13; nothing sent); `sending` → `saved` | `savedPrivate` | `duplicate` | `unreachable` | `tooLarge` | `tooLong` | `refused` | `tokenRefused`; `unreachable` → `sending` (Réessayer, attempt + 1).

- `saved`, `savedPrivate` and `duplicate` close the sheet 1.5 s after they appear (`completeRequest`). The 5 seconds of the spec run from Enregistrer to the confirmation.
- « Annuler » stays active while sending: it cancels the task and closes the sheet. The capture may already be on the server; a new share would draw a new capture id (Risks).
- `tooLarge`, `tooLong`, `nothingToSave`, `refused`, `tokenRefused`, `preparationFailed`: « Fermer » closes, with `cancelRequest`.
- The transitions live in `Core.ShareFlow` (attempt counter, frozen request), tested by `swift test`; `ShareModel` only runs them on the main actor.

### D10 — One token file for both themes

- `app/src/ui/theme/tokens.json`: `colors.light` and `colors.dark` with the same names (`background`, `surface`, `text`, `textMuted`, `accent`, `success`, `warning`, `danger`, `border`), `spacing`, `radius` (card 16, the E1 finding), `textSizes` (`title`, `body`, `caption`).
- App: `src/ui/theme/` reads the JSON (`resolveJsonModule`, from `expo/tsconfig.base`, confirmed in task 5.1) and exposes `useTheme()`, which picks light or dark from `useColorScheme()` (light when `null`). The root layout wraps the `Stack` in `ThemeProvider` re-exported by `expo-router`, from `DefaultTheme` or `DarkTheme` with the token colours.
- Extension: `expo-target.config.js` `require`s the JSON and maps each colour to `{ light, dark }` (the type the installed plugin reads, As built); SwiftUI uses `Color("success")`. Its texts use SwiftUI text styles (`.body`, `.headline`), which follow Dynamic Type natively; only colours are shared.
- A jest test evaluates `expo-target.config.js` and compares its colours with the tokens (spec app-shell).

### D11 — App foundation

- Folders: `src/ui/theme/` (tokens, `useTheme`), `src/ui/` (`ThemedText`, `Screen`), `src/features/home/HomeScreen.tsx`, `src/features/health/ServerStatus.tsx` restyled as the pill of screen 1; `src/app/_layout.tsx` and `src/app/index.tsx` stay thin (conventions-app.md, « Organisation »).
- Every text goes through `ThemedText`: size from `textSizes`, `allowFontScaling` never set to false, no `maxFontSizeMultiplier` (conventions-app.md, « Interface »).
- `GET /healthz` stays the only call; it does not check the token (public route). A wrong token is told by the extension (screen 11); no new call is added (E5-08 shows the server's state with Réglages).
- Tests (jest, React Native Testing Library, network simulated at the generated client): spec app-shell. Appearance is simulated by mocking `useColorScheme` from `react-native`.

### D12 — Swift conventions and checks

- `swift format` from the Xcode toolchain (no package), rules in `app/targets/.swift-format` (2-space indent and 100 columns, as the prototype). Lint on the files git does not ignore (tracked, or new and not ignored), so a new file is linted before its first commit and the generated config, ignored, never matters.
- Make targets: `lint-swift` (`git ls-files -z --cached --others --exclude-standard -- 'app/targets/*.swift' | xargs -0 swift format lint --strict --configuration app/targets/.swift-format`), `format-swift`, `test-swift` (`cd app/targets && swift test`), `check-swift: lint-swift test-swift`, added to `make check`. `lint-app` and the Linux `app` job are untouched.
- lefthook: a `swift-format` command with two globs, `app/targets/*.swift` and `app/targets/**/*.swift` (lefthook 2.2.2's `**` does not match `app/targets/Package.swift`), lint of the staged files.
- CI: job `swift` on a macOS runner, `needs: changes`, filter `swift` = `*ci` + `app/targets/**` + `api/**` (the tests read `api/openapi.bundled.gen.json` to compare the request members with the contract), Xcode selected explicitly to the version of the Mac (`xcodebuild -version`, Xcode 27.1 on 2026-10-26) or the closest on the runner image, then `make check-swift`; timeout 15 min; added to the `needs` of `ci-ok` (ADR-0034). Free for a public repository; the queue for a macOS runner can add minutes. The image's Xcode versions are unverified until the first run.
- `conventions-app.md` gets a « Swift de l'extension » section (layout, `Core` rules, format, tests, no logs); ADR-0030 and ADR-0033 are not amended (proposal, Impact).

### D13 — Building

- `app/scripts/build-ios-sim.sh` (`make build-ios-sim`): `npx expo prebuild --clean -p ios`, then `xcodebuild` Debug for `generic/platform=iOS Simulator`, no signing. Needs `HIPPO_API_TOKEN` (any 32 characters) and the default local URL. Part of the definition of done, since the CI does not build the target.
- `app/scripts/build-ipa.sh` (`make ipa`): `prebuild --clean`, `xcodebuild archive` Release for `generic/platform=iOS` with `CODE_SIGNING_ALLOWED=NO`, `Payload/` zipped as `Hippo.ipa`, then zipped again for AirDrop (runbook E1). Needs the `https` URL and the token.
- Both run prebuild and build in one command with the same environment (D1). Outputs in `app/build/` (git-ignored).
- **Token in the build output, checked on 2026-11-13** (Xcode 27.1, fake sentinel token): `make build-ios-sim` (`-quiet`) succeeded, and its output never holds the token. Then a full-output `xcodebuild` (no `-quiet`), with the token in the environment and the « Check Pods Manifest.lock » script phase made to fail (`ios/Pods/Manifest.lock` altered, then restored), ended in `BUILD FAILED` (65): the log prints the `export` lines of each script phase, which are build settings (`HOME`, `PATH`, `USER`…) and no shell variable (`HIPPO_API_TOKEN`, `HIPPO_API_URL` and `LANG` absent), and the token appears nowhere in its 6 836 lines. The token stays in the built products (the generated Swift file, the app's embedded config), as accepted in D1.

### D14 — Logs

The extension writes no log at all: no `print`, `os_log` or `Logger`, no measure screen. A failure is told on screen only. `lint-swift` cannot check it; the review does (`code-reviewer` checklist line in tasks).

### Packages, contract, migration, prompt, rules

- No Go package, no `api/openapi.yaml` change, no migration, no prompt or fiche schema change.
- App folders: `app/src/ui/`, `app/src/features/home/`, `app/src/features/health/`, `app/src/app/`, `app/plugins/`, `app/scripts/`, `app/targets/`; `app/app.config.ts`, `app/package.json` (`@bacons/apple-targets` 5.0.0 exactly).
- RG-90: no new server query. RG-12: the extension sends `is_private` with every capture; the backend's guarantee is unchanged and already tested. RG-81: no AI call.

## As built (tranche A)

Tasks 1.2, 1.3, 2.1 to 2.3, 3.1 to 3.6 and 6.1. Deviations from the decisions above, and facts read in the installed `@bacons/apple-targets` 5.0.0 that correct the Context:

- **No App Group warning at all.** In 5.0.0 the warning is emitted only when the target config defines `entitlements` (`build/with-widget.js`, inside `if (entitlementsJson)`); ours defines none, so the prebuild prints nothing about App Groups. Only the `ios.appleTeamId` warning remains (absent `HIPPO_APPLE_TEAM_ID`). The runbook (task 7.2) must not announce an App Group warning.
- **Colour sets take `{ light, dark }`, not `{ color, darkColor }`.** `build/config.d.ts` (`DynamicColor`) and `withConfigColors` read `color.light` and `color.dark`; the README's `color`/`darkColor` is out of date. D10 and task 5.1 map the tokens to `{ light, dark }`.
- **Plugin test in JavaScript** (`app/plugins/with-share-config.test.js`, `@jest-environment node`): a TypeScript test needs Node's types, and `@types/node` is not a direct dependency (no new package). `app/eslint.config.js` declares jest's globals for `plugins/**/*.test.js`, and ignores `build/`, `ios/`, `targets/.build/`; `app/.prettierignore` ignores `build/` and `targets/.build/`.
- **One URL rule for the app and the extension.** The plugin exports `resolveApiUrl`, which `app.config.ts` uses for `extra.apiUrl` and for `NSAllowsLocalNetworking`: the app also drops trailing slashes, and an empty `HIPPO_API_URL` means the default URL. The plugin is registered as `./plugins/with-share-config` after `@bacons/apple-targets`.
- **`make ipa`** also refuses a non-`https` `HIPPO_API_URL` before the prebuild, fails when `PlugIns/HippoShare.appex` is missing from the archived app, and writes `app/build/Hippo.ipa` plus `app/build/Hippo.ipa.zip` (AirDrop). Both scripts export `LANG=en_US.UTF-8` when unset (CocoaPods refuses another encoding). `check-tooling` runs shellcheck on `app/scripts/*.sh`.
- **`lint-swift` lints the files git does not ignore** (`git ls-files --cached --others --exclude-standard`), not only the tracked ones, so a new file is linted before its first commit; the generated configuration stays out (ignored). `.swift-format` is the full configuration dumped from the Xcode 27.1 toolchain (2 spaces, 100 columns), so the rules do not move with the toolchain. The lefthook `swift-format` command has two globs, `app/targets/*.swift` and `app/targets/**/*.swift`: lefthook 2.2.2's `**` does not match `app/targets/Package.swift`.

The French texts of every screen are in `Core` (`ShareState.screen`, `ScreenText`), so the scenarios check them and the views only show them.
- **Small decisions** (after review): « Enregistrer » is not offered for a note whose text is blank (`canSave`, now scenario « Blank note text cannot be saved »; the server would refuse it as `empty-note`); a blank problem `detail` counts as absent (fallback text); a file whose size cannot be read is unreadable (nothing-to-save); the accompanying text is the first text left non-empty once the URL is removed (D4); the too-long screen shows the size of the JSON body for a link or a note, of the capture note for an image; a server `413 image-too-large` shows the local size of the image; the multipart text parts carry no `Content-Type` header; a link made from a text takes the next text as its accompanying text.
- **`ShareViewController`** closes the sheet at once and sends nothing until tasks 4.1 to 4.3; `Probe.swift` and its test are removed (task 3.6).

Production findings: 21 on `main`, 29 with `@bacons/apple-targets`, 27 with the override (1 low, 26 moderate, no high or critical). The moderate ones left that come with `@bacons/apple-targets` are `uuid` 8.3.2 (through `@bacons/xcode`), `glob`, and its SDK 55 copies of `@expo/prebuild-config` and `@expo/config-plugins`: prebuild-time tools that read the project's own files, nothing embedded in the app or the extension. **Remove the override** when `@bacons/apple-targets` (through `@bacons/xcode` and `@expo/plist`) depends on a fixed `@xmldom/xmldom` itself; a bump of `@bacons/apple-targets` checks it.

## Risks / Trade-offs

- [Memory of the extension, ~120 MB, with a 48 Mpx HEIC or a 20 MB PNG] → file reading, ImageIO thumbnail, upload from file (D5, D6); JPEG conversion of an odd format decodes the whole image (rare). Unverified until Q16.
- [An image offered only as an object (`UIImage`), the screenshot editor maybe] → every other image type is tried as a file first (As built, tranche B); the object path decodes the whole image, about 190 MB for 48 Mpx, over the extension's ~120 MB, and a large screenshot can approach it. Unverified until Q21; if it happens, the fix is a reduced decode or refusing the share, decided with Ghislain.
- [Photos never offers HEIC or PNG to an extension] → JPEG is sent, as before; Q1 records it; no rework.
- [A 48 Mpx HEIC of more than 8 bits gives no copy for the AI] (spec-v1, « Copie de l'image », known cases) → Q5 checks the next batch; if it happens, the choice between keeping HEIC and preferring JPEG for photos goes back to Ghislain.
- [Original images keep their GPS position on the NAS and in the export] → RG-38 strips it from the AI copy; Photos' own « Options » can leave it out; accepted (proposal, Impact).
- [An image near 20 MiB with a capture note near 1 MiB makes a multipart body over the server's 21 MiB] (each part within its own limit, plus about 500 bytes of part headers) → the server answers `413 about:blank`, told as screen 10 with « Le serveur a refusé ce partage (HTTP 413). »; nothing is stored. Not checked before the send: no existing scenario covers it and telling it otherwise needs a new screen text from Ghislain. Accepted for V1 (it takes a near-limit image and a megabyte of typed note); found by the review of tranche A.
- [Activation rule semantics for a share mixing types] → unverified; Q3, Q7, Q9.
- [Scope of `NSAllowsLocalNetworking` on iOS 27] → unverified; unused by a device build, which only takes `https` (D1).
- [« Annuler » during a send] → the capture may exist without a confirmation; a new share draws a new capture id, so an image or a note could be captured twice. Accepted: it needs a deliberate cancel then a new share.
- [A `200` after « Réessayer » for a link that was a real duplicate] → shown as « Enregistré », not « Déjà dans Hippo »: the item is safe either way (decided on 2026-11-13).
- [macOS runner image without the Mac's Xcode] → closest version; `swift format` rules pinned by `.swift-format`; first CI run checks (task 6.3).
- [`overrides` forces `@xmldom/xmldom` 0.8.15 under `@bacons/xcode`, outside the `~0.7.0` its `@expo/plist` declares] → only `DOMParser.parseFromString` is used, checked by the builds of As built; the override is removed once apple-targets ships a fixed `@xmldom/xmldom` (As built, `npm audit`); moderate findings of prebuild-time tools remain, accepted.
- [apple-targets rewrites the Xcode project at each prebuild] → version pinned to 5.0.0; a bump is a deliberate change with a simulator build.
- [Token readable in the `.ipa`] → personal use, tailnet only (ADR-0016, ADR-0027); the `.ipa` is never published.
- [SideStore weekly refresh, `-80045`] → unchanged, runbook.
