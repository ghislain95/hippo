# Design

## Context

See proposal.md for the why. State on 2026-10-26:

- `app/` is the walking skeleton (Expo SDK 58, React Native 0.88, expo-router), with no native target. Nothing iOS has been built yet on this Mac.
- Xcode 27.1 is installed, but its license is not accepted and `xcode-select` points to the Command Line Tools. Both need `sudo`, so Ghislain runs them. Until then, no iOS build is possible.
- Tailscale.app is installed on the Mac, with no account. SideStore is not installed.
- ADR-0014 already names a minimal Swift extension as its fallback. This design takes it first, as framed with Ghislain.
- `@bacons/apple-targets` 5.0.0 (peer `expo >= 52`) generates Xcode targets from a `targets/<name>/` folder at `npx expo prebuild`. For the `share` type it expects a `ShareViewController` principal class. The target's own `Info.plist` is left to us, and entitlements are only written when declared.
- CI runs on pull requests and on `main`, and the lefthook globs cover `backend/` and `app/` only. A `spikes/` folder that never reaches a pull request is outside both.

## Goals / Non-Goals

**Goals:**

- Answer each question of E1 with an observed result, not an assumption. Give Ghislain the exact steps he can follow alone on the iPhone.
- Keep the prototype close enough to the real contract (`POST /api/items`, Bearer token) that E5-02 can reuse what it learns.

**Non-Goals:**

- Code quality beyond "readable and honest": no lint setup, no app tests, no accessibility pass. The code is deleted before the pull request.
- `client_id`, duplicates, validation errors: the echo server accepts any well-formed capture.

## Decisions

### D1. Layout: two self-contained projects under `spikes/e1-ios/`

- `spikes/e1-ios/app/`: an Expo project with its own `package.json` and `node_modules`, the same SDK and React Native versions as `app/`.
- `spikes/e1-ios/echo/`: a Go module of its own (`go.mod`, standard library only).
- Neither is referenced by the `Makefile`, the CI or `app/`.

Alternatives: building the prototype inside `app/` would pull its dependencies and native folders into the real app. A workspace shared with `app/` would couple their installs. Both are rejected.

### D2. Share extension: Swift and SwiftUI, generated by `@bacons/apple-targets`

- `targets/share/expo-target.config.js` declares `type: "share"`, with no `entitlements` (so no App Group) and a deployment target matching the app.
- `ShareViewController` is a `UIViewController` that hosts a SwiftUI view through `UIHostingController`.
- The view reads the shared item with `NSItemProvider`:
  - `public.url` makes a link;
  - `public.plain-text` makes a link when `NSDataDetector` finds a single URL in it, and a note otherwise (Instagram often shares text);
  - `public.image` makes an image.
- It shows a preview, the capture note (hidden for a note, RG-07), the Privé toggle unchecked (RG-10) and Enregistrer.
- Our own `Info.plist` restricts `NSExtensionActivationRule` to one web URL, one text or one image, instead of the plugin's default `TRUEPREDICATE`.

Alternatives:
- `expo-share-extension` runs React Native in the extension. That is heavy against the extension memory limit, its compatibility table stops at SDK 54, and it creates an App Group by default.
- A hand-made Xcode target would be overwritten by every `prebuild --clean`.

### D3. Requests mirror the contract

The extension sends `POST /api/items` with `Authorization: Bearer <token>`:

- a link or a note as JSON `CaptureRequest` (`url` or `note`, `user_note`, `is_private`);
- an image as `multipart/form-data` with `image`, `user_note` and `is_private` (`CaptureImageRequest`).

The app's network tab calls `GET /ping`, which is not in the contract and only serves the prototype.

### D4. Server URL and token injected at build time, from one local file

ADR-0014 says so, and without an App Group the extension cannot read the app's settings.

- `npm run configure` reads `HIPPO_SPIKE_URL` (default `http://127.0.0.1:8787`). It creates a random token in `spikes/e1-ios/.spike-token` when missing, and writes from them:
  - `targets/share/SpikeConfig.swift`, read by the extension;
  - the `Info.plist` of the extension;
  - `.spike.json`, read by `app.config.ts` into `extra` for the app.
- The echo server reads the same token file. All generated files are gitignored.
- An `http` URL (simulator only) adds `NSAllowsLocalNetworking` to both `Info.plist`. An `https` URL adds no ATS key at all, so the 4G test proves E1-03 "sans exception ATS".

Alternative: build settings in an `.xcconfig` read by `Info.plist`. That adds a file that prebuild must keep linked, for the same result.

### D5. Glass test screen

- The app root is `NativeTabs` (`expo-router/native-tabs`) with two tabs.
- **Verre** shows `GlassView` (`expo-glass-effect`) over a colorful background, in its styles, tinted and interactive. Next to it, a `Host` from `@expo/ui/swift-ui` holds native SwiftUI controls (button, toggle, picker, slider).
- **Réseau** shows the server URL, calls `/ping`, and shows the status and latency.

Versions come from `npx expo install`, never pinned by hand.

### D6. Echo server

- It listens on `127.0.0.1:8787` only, so it is reachable from the tailnet through `tailscale serve` and never from the LAN.
- `GET /ping` returns `{"ok": true}`; every route, `/ping` included, requires the Bearer token. `POST /api/items` checks the token, then accepts the JSON or multipart forms. It answers `201` with the form, the URL or note length, and the image size.
- It logs one line per request: method, route, form, sizes, status. It never logs the token, the note text or the URL query.
- Received images are written to `echo/received/` (gitignored), so Ghislain can check that they are intact.
- A Go test covers: bad token, link, note, image, and malformed body.

### D7. Three ways to install, each answering one question

| Path | Built by | Answers |
| --- | --- | --- |
| Simulator, Debug, `npx expo run:ios` | the agent | does it build, does sharing from Safari reach the echo server |
| iPhone through Xcode, Release, Personal Team | Ghislain | can a free account sign an app with a share extension (E1-01) |
| iPhone through SideStore, unsigned `.ipa` re-signed by SideStore | Ghislain | install and weekly refresh from the iPhone (E1-02) |

The on-device builds use the Release configuration, so the JavaScript is embedded. The 4G test happens away from the Mac, where a development build would wait for Metro. The backlog wording "development build" in E1-01 is met on the simulator. The `.ipa` comes from `xcodebuild archive` with `CODE_SIGNING_ALLOWED=NO`, packed as `Payload/*.app` by an `npm run ipa` script.

### D8. Measures shown by the extension

After a send, the confirmation shows:

- the time from opening the extension to the server's answer;
- the extension's physical memory footprint (`task_vm_info.phys_footprint`).

Ghislain notes them in the QA checklist, for a link and for a large screenshot.

### D9. Where results live

- The results report is `results.md` in the change folder, archived with the change. It is written in French, unlike the other artifacts: it is the checklist Ghislain fills on the iPhone and reads to steer (ADR-0028).
- The lasting procedure goes to `docs/runbook-ios.md`.
- The decision goes to ADR-0014's status, or to a new ADR through `/new-adr` if the result departs from it. A Swift extension built with `@bacons/apple-targets` replaces a library that `docs/spec-v1.md` lists, which is worth its own ADR.
- A commit `chore(ios-prototype): remove the prototype code` empties `spikes/` before the pull request.

## Risks / Trade-offs

- [The Xcode license and `xcode-select` need `sudo`] → Builds wait for Ghislain. In the meantime the agent uses `DEVELOPER_DIR` and writes everything that does not need a build.
- [A free account allows 10 App IDs per 7 days, and the app with its extension takes 2] → Fixed bundle identifiers (`com.ghislain95.hippo.spike`, `.share`), reused by every install. The runbook warns against changing them.
- [SideStore may rewrite bundle identifiers when re-signing] → No impact without an App Group. This is the reason ADR-0014 avoids one. Recorded in the results.
- [Instagram may share only text, or hide third-party extensions] → URL detected in text (D2). If the extension does not appear, it is recorded as a result, not worked around.
- [iOS keeps one VPN active: Tailscale and SideStore's VPN] → The runbook gives the exact switch for the weekly refresh. Their coexistence is a QA step.
- [`@bacons/apple-targets` 5.0.0 with SDK 58 is untested here] → Checked at the first prebuild. If it breaks, the fallback is a target added by a small local config plugin, recorded in the results.
- [Liquid glass needs iOS 26 or later] → `GlassView` falls back to a plain view on earlier versions. The screen shows `isLiquidGlassAvailable()`.
- [Large images against the extension memory limit (about 120 MB)] → The footprint is measured (D8). Streaming the upload from a file is a finding for E5-02, not prototype work.
- [The token sits in plain text in the extension binary] → It is a throwaway token for a server reachable only on the tailnet. The real app's token handling stays ADR-0016's.

## Migration Plan

None: nothing is deployed and `main` receives docs only.
